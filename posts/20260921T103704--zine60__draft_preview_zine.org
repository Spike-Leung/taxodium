- [[https://karpathy.bearblog.dev/the-append-and-review-note/][The append-and-review note]] by Andrej Karpathy

  文章分享了一種「追加與回顧」的笔記方法，具體做法是：
  - 只有一個笔記文件，文件最好能方便地多端同步

    #+begin_quote
    維護多則筆記，還要管理並將它們分類到資料夾和層層相套的子結構中，會耗費太多心力。
    只有一則筆記，按 CTRL+F 搜尋就簡單又方便。

    [[https://karpathy.bearblog.dev/the-append-and-review-note/#:~:text=Data,backup][Source]]
    #+end_quote

  - 新的笔記追加在最上方，可以適當加一些 tag 方便查找，例如 ~book:~ 、 ~moive:~
  - 有空時就回頋一下

    #+begin_quote
    隨著新內容不斷加到最上方，其他內容便像受重力牽引般逐漸沉到下方。
    偶爾我會往下捲動、快速瀏覽筆記。
    如果發現有什麼值得繼續留意，就簡單複製貼上，把它移回上方。
    有時候，遇到彼此相關的筆記，我會把它們合併、整理、分組或修改。
    我很少刪除筆記。
    不值得反覆關注的內容自然會繼續往下沉。
    它們並沒有消失，只是不值得一直放在心上。

    [[https://karpathy.bearblog.dev/the-append-and-review-note/#:~:text=Review%2E%20As,mind][Source]]
    #+end_quote

  這個笔記文件就是一個可以隨時且方便打開的 inbox，想到什麼就往裡面先放著，等有空再來处理。

  #+begin_quote
  _把事情記下來時，我覺得自己可以立刻放下它、清空工作記憶，並全心投入當下的其他事情。_
  我相信之後回顧時，可以重新檢視這個想法，並在時間較充裕時好好整理。

  [[https://karpathy.bearblog.dev/the-append-and-review-note/#:~:text=When%20I%20note,more%20time][Source]]
  #+end_quote

  我之前記一些临時笔記會分到不同的文件裡，
  多個文件確實會增加心智負擔，都放在一個文件裡確實會更好，我接下在會實踐一下這個方法。

- [[https://michaelheap.com/i-dont-want-the-details/][I don't want the details]] by Michael

  #+begin_quote
  幾個月前，我被拉進一場電話會議，
  與工程部門的對口同事及其主管（碰巧也是我們的工程資深副總裁）一起討論一件不該出差錯的事。
  事情出了問題。雖然並非災難性事件，但重要到讓我得和一位資深副總裁開會。

  我開始解釋事情是怎麼發生的，對方卻打斷我說：「Michael，我不想聽細節。」

  對方接著說：

  「我知道，如果我們深入討論細節，背後的原因都會很合理。
  你會解釋發生了什麼，我會明白大家為什麼做出那些決定，也會體諒你。

  但之後同樣的事還是會再次發生。

  所以我不想聽細節。我想知道我們要做出哪些改變。」

  一開始，我覺得「我不想聽細節」聽起來有些輕蔑。
  他們不了解細節，怎麼能做出明智的決定？

  後來我明白，「我不想聽細節」並不是輕蔑的表現。
  這位主管相信我們有能力處理問題，並且是在說：「我已經相信你了。現在來談談接下來該怎麼做。」

  [[https://michaelheap.com/i-dont-want-the-details/#:~:text=A,next%22%2E][Source]]
  #+end_quote

  想解釋問題細節，部分原因是因為怕擔責和怕失去信任吧。
  如果上級并沒有指責的意思，也很相信下屬，或許就可以省點口舌，把重點放在怎麼避免問題再次發生。

  給問題找到一個解釋，會讓人鬆一口氣，讓問題不再紧迫。
  但解釋不是解决方案，要思考的是，如果同樣的問題再次發生，做出什麼改變會讓結果不同。

  #+begin_quote
  如果你的事後檢討滿是「我們應該早點讓支援團隊參與」和「我們需要加強溝通」這類句子，
  或是我個人最愛的「下次我們會更小心」，那你手上只是一堆披著進步外衣的願望。

  [[https://michaelheap.com/i-dont-want-the-details/#:~:text=fix-,If,progress][Source]]
  #+end_quote

- [[https://blog.gaborkoos.com/posts/2026-09-08-Half-Past-Fetch/][Half Past Fetch]] by Gabor Koos

  用 [[https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API][Fetch API]] 發起一次請求，一般會這麼寫：

  #+begin_src javascript
    const response = await fetch(url) // awaits the headers
    const body = await response.json() // awaits the body
  #+end_src

  ~await fetch(url)~ 完成後，拿到的是 [[https://developer.mozilla.org/en-US/docs/Glossary/Response_header][Response header]]，但此時還沒获取到 [[https://developer.mozilla.org/en-US/docs/Web/API/Response/body][body]]，
  可以基於 header 的值决定是否要获取 body 及後續的操作。
  例如，如果 header 返回的狀態碼是 404 或 500，也許就沒必要請求 body，可以及早關閉連接。

  文章還分享了其它一些 Fetch API 的細節。

#+begin_quote
俺也一樣是一個網絡迷因，出自央視版《三國演義》第一集桃園結義的劇情。
關羽三次用得體的語言向劉備表達自己心意，而張飛三次附和道「俺也一樣」。

「俺也一樣」是不是表達意見？是。
那麼「俺也一樣」對討論有沒有幫助？沒有。
因為它不提供任何新信息，而討論想要獲得進展，需要的是事實和論述。
所以不要在討論裡說「俺也一樣」。
#+end_quote
