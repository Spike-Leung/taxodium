* 什么是 Webmention
:PROPERTIES:
:CUSTOM_ID: D459C268-A454-4D43-9E49-97D0A90C2F67
:END:

#+begin_quote
Webmention 是一种通知，表明一个 URL 链接到另一个 URL。

例如，Alice 在她的博客上写了一篇有趣的帖子。
随后 Bob 在自己的网站上写了一篇回复她的帖子，并链接回 Alice 的原始帖子。
Bob 的发布软件向 Alice 发送一个 Webmention，通知她的文章被回复了，
Alice 的软件可以将该回复显示为原始帖子上的评论。

[[https://www.w3.org/TR/webmention/#introduction-p-1:~:text=A%20Webmention%20is,the%20original%20post.][Source]]
#+end_quote

Webmention 和评论差不多，只是它的门槛相对高一点，需要你写一篇文章[fn:1]，并链接到你想评论的文章。

如果对方支持了 Webmention，你发送 Webmention 通知后，对方就会将你的内容显示出来。

* 为什么接入 Webmention
:PROPERTIES:
:CUSTOM_ID: E55EE851-CF6C-4FC6-A4F8-94FD38BFA17F
:END:

#+begin_quote
*实现跨站点的对话。*
当你链接到某个网站时，你可以发送一个 Webmention 来通知它。
如果该网站支持 Webmention，那么该网站可能会将你的帖子显示为评论、赞或其他回应，
就这样，你就实现了从一个站点到另一个站点的对话！

[[https://indieweb.org/Webmention#:~:text=Enables%20cross%2Dsite%20conversations.%20When%20you%20link%20to%20a%20website%2C%20you%20can%20send%20it%20a%20Webmention%20to%20notify%20it.%20If%20it%20supports%20Webmentions%2C%20then%20that%20website%20may%20display%20your%20post%20as%20a%20comment%2C%20like%2C%20or%20other%20response%2C%20and%20presto%2C%20you%E2%80%99re%20having%20a%20conversation%20from%20one%20site%20to%20another!][Source]]
#+end_quote

我觉得 Webmention 和集成在博客中的评论系统是类似的。

如果你要回应一篇文章，通过 Webmention，你需要写一篇文章链接到这篇文章，并发送一个 Webmention 通知。
通过如 [[https://brid.gy/][Bridgy]] 之类的服务，也可以收集社交网络上（Blusky、Mastodon 等）关于文章的回应，例如点赞、转发等。

但我觉得并没有比集成于博客的评论系统更方便。

从数据层面看，除非自己买服务器搭建 Webmention，否则用第三方提供的服务，数据依然不在自己的手上。

所以我为什么要接入 Webmention？

最开始是在 [[https://www.owenyoung.com/blog/de-roboticization/#2-xie-bo-ke%20:~:text=%E6%88%91%E7%9A%84%E5%8D%9A%E5%AE%A2%E6%B2%A1%E6%9C%89%E8%AF%84%E8%AE%BA%E5%8A%9F%E8%83%BD%EF%BC%8C%E5%9B%A0%E4%B8%BA%E8%AF%84%E8%AE%BA%E5%8A%9F%E8%83%BD%E4%BC%9A%E5%85%B6%E5%AE%9E%E4%BC%9A%E8%AE%A9%E6%88%91%E5%BC%95%E5%85%A5%E7%A4%BE%E4%BA%A4%E7%BD%91%E7%BB%9C%E7%9A%84%E5%8C%85%E8%A2%B1%E6%84%9F%E3%80%82%E6%88%91%E8%A7%89%E5%BE%97%E8%A7%A3%E5%86%B3%E8%BF%99%E4%B8%AA%E9%97%AE%E9%A2%98%E7%9A%84%E5%A5%BD%E5%8A%9E%E6%B3%95%E6%98%AF%E5%BC%95%E5%85%A5webmention%E7%9A%84%E5%8A%9F%E8%83%BD%EF%BC%8C%E5%A6%82%E6%9E%9C%E6%9C%89%E4%BA%BA%E6%83%B3%E8%A6%81%E5%9B%9E%E5%BA%94%EF%BC%8C%E5%BE%97%E6%8F%90%E4%BA%A4%E8%87%AA%E5%B7%B1%E7%9A%84%E5%9B%9E%E5%BA%94%E7%BD%91%E5%9D%80%EF%BC%8C%E8%80%8C%E4%B8%8D%E6%98%AF%E5%9C%A8%E4%B8%80%E4%B8%AA%E7%AE%80%E5%8D%95%E7%9A%84%E8%AF%84%E8%AE%BA%E6%A1%86%E9%87%8C%E7%95%99%E4%B8%8B%E4%B8%89%E8%A8%80%E4%B8%A4%E8%AF%AD%E3%80%82%E8%BF%99%E6%8F%90%E9%AB%98%E4%BA%86%E8%AF%84%E8%AE%BA%E7%9A%84%E6%88%90%E6%9C%AC%EF%BC%8C%E9%BC%93%E5%8A%B1%E6%83%B3%E8%A6%81%E7%95%99%E8%A8%80%E7%9A%84%E4%BA%BA%E6%8B%A5%E6%9C%89%E8%87%AA%E5%B7%B1%E7%9A%84%E5%8D%9A%E5%AE%A2%EF%BC%8C%E4%BB%A5%E5%8F%8A%E5%86%99%E4%B8%80%E4%BA%9B%E7%BB%8F%E8%BF%87%E6%80%9D%E8%80%83%E7%9A%84%E8%AF%9D%E8%AF%AD%E3%80%82%E6%88%91%E7%9A%84%E5%8D%9A%E5%AE%A2%E5%B7%B2%E7%BB%8F%E6%94%AF%E6%8C%81%E4%BA%86%20Webmention%EF%BC%8C%E6%88%91%E5%9C%A8Now%2C%20I%E2%80%99m%20in%20IndieWeb%3F%E9%87%8C%E6%9C%89%E8%AE%B0%E5%BD%95%E6%88%91%E7%9A%84%E5%AE%9E%E7%8E%B0%E3%80%82][我想让自己说话不那么“端着” | Owen Young]] 中了解到 Webmention，当时觉得有些麻烦。

最近网上冲浪的时候，看到不少博客都有集成 Webmention，然后了解了一下  [[https://webmention.io/][webmention.io]] 的使用，看起来不麻烦，就想着集成看看。

* 如何接入 Webmention
:PROPERTIES:
:CUSTOM_ID: D55D3AFA-42A0-4D14-A52F-FB34162E31DD
:END:

如果是自己搭建的话，可以参照 [[https://www.w3.org/TR/webmention][Webmention 规范]] 实现。
也可以找现成的工具，[[https://indieweb.org/Webmention][Webmention | IndieWeb]] 里罗列了很多工具和服务。

我目前实现很简单，主要依赖 [[https://webmention.io/][webmention.io]] 提供的服务。

** 作为接收方
:PROPERTIES:
:CUSTOM_ID: 9119BFDC-A4D1-4D2D-A736-24A274102F47
:END:

接收我使用 [[https://webmention.io/][webmention.io]] 提供的服务，按照 [[https://indielogin.com/setup][How to Set Up Your Website for IndieLogin.com]] 的说明进行设置。

我用 GitHub 进行验证，需要在 GitHub Profile 中包含我的网站，同时在网站添加一个链接。

#+CAPTION: 我的 GitHub Profile 页面，我把网站的地址添加到了 Profile 中
[[file:images/add-webmention-to-blog/github-profile.png]]

#+begin_src html
  <head>
    <!-- 省略其他内容 -->
    <link href="https://github.com/spike-leung" rel="me">
    <!-- 省略其他内容 -->
  </head>
#+end_src

这样就能通过 webmention.io 的验证了。

接下来按照 webmention.io 提供的 API 获取 Webmentions 的数量和内容，
需要在页面上添加 HTML 元素，写 [[file:js/webmention.js][一些 JS 代码]] 调用 API 渲染数据[fn:2]，再写点 CSS 优化一下样式。

搭建好之后，可以用 [[https://webmention.rocks/#:~:text=Testing%20your%20Receiver][Webmention Rocks!]] 提供的服务进行测试。

你可以在页面底部看到这篇文章的 Webmentions，
也欢迎你给我发送 Webmentions，这样我也可以测试 Webmentions 的展示。

** 作为发送方
:PROPERTIES:
:CUSTOM_ID: 582BF4C8-77F8-4E6E-B823-8C9941F41233
:END:

#+CAPTION: 我向 https://aaronparecki.com/2018/06/30/11/your-first-webmention 发送了 Webmention 后在对方页面中的展示。
[[file:images/add-webmention-to-blog/webmention-reply.png]]

作为发送方，你只需要在你的文章中包含对方的链接，就可以向对方发送 Webmention 了。[fn:3]

但是如果你想让你发送的内容更丰富一些，就需要通过 [[https://microformats.org/wiki/Main_Page][microformats]] 标记网站信息，
如用户名、头像、内容、你要提及的链接等，从而让 Webmention 解析展示。

最主要的标记是 [[https://microformats.org/wiki/h-card][h-card]] 和 [[https://microformats.org/wiki/h-entry][h-entry]]，前者标记用户信息；
后者标记内容信息，标记的部分会作为 Webmention 的内容呈现。

#+attr_html: :class u-in-reply-to e-content
关于 h-card 和 h-entry 的作用，推荐看 [[https://aaronparecki.com/2018/06/30/11/your-first-webmention][Sending your First Webmention from Scratch]]，
文章循序渐进地引导你添加相应的标记，并且有对应的示例，
同时文章本身也可以用来测试 Webmention 的发送。

我在往自己博客添加的过程中折腾了很久，也分享一些我的经验。

microformats 这些标记，可以和 HTML 做类比，它也是有层级关系的，最终会解析成一个 JSON 的树形结构。
在你测试的时候，可以从 [[https://microformats.org/wiki/parsers][Microformats Parsers]] 找一个 parser 检查你的文章解析出来的内容。

*关于 h-entry*

[[https://microformats.org/wiki/h-entry#:~:text=the%20%22datetime%22%20property.-,what%20is%20the%20bare%20minimum%20list%20of%20required%20properties%20on%20an,a%20nested%20h%2Dcard%20with%20author%20details%20like%20name%2C%20photo%2C%20url.,-Examples%20in%20the][what is the bare minimum list of required properties on an h-entry]] 中回答道，没有任何 h-entry 的属性是强制要求的。

但推荐至少包含：
- [[https://microformats.org/wiki/h-entry#:~:text=e%2Dcontent%20%2D%20full%20content%20of%20the%20entry][e-content]] 标记文章内容，被标记的内容会作为 Webmention 的内容被发送
- [[https://microformats.org/wiki/h-entry#:~:text=p%2Dname%20%2D%20entry%20name/title][p-name]] 标记文章标题
- [[https://microformats.org/wiki/h-entry#:~:text=p%2Dauthor%20%2D%20who%20wrote%20the%20entry%2C%20optionally%20embedded%20h%2Dcard(s)][p-author]] 标记作者信息，一般会和 h-card 结合使用

一些我建议加上的：
- [[https://microformats.org/wiki/h-entry#:~:text=u%2Din%2Dreply%2Dto%20%2D%20the%20URL%20which%20the%20h%2Dentry%20is%20considered%20reply%20to%20(i.e.%20doesn%E2%80%99t%20make%20sense%20without%20context%2C%20could%20show%20up%20in%20comment%20thread)%2C%20optionally%20an%20embedded%20h%2Dcite%20(reply%2Dcontext)%20(example)][u-in-reply-to]] 标记你回应的链接。此外 [[https://microformats.org/wiki/h-entry#:~:text=u%2Dlike%2Dof%20%2D%20the%20URL%20which%20the%20h%2Dentry%20is%20considered%20a%20%E2%80%9Clike%E2%80%9D%20(favorite%2C%20star)%20of.%20Optionally%20an%20embedded%20h%2Dcite][u-like-of]]、[[https://microformats.org/wiki/h-entry#:~:text=u%2Drepost%2Dof%20%2D%20the%20URL%20which%20the%20h%2Dentry%20is%20considered%20a%20%E2%80%9Crepost%E2%80%9D%20of.%20Optionally%20an%20embedded%20h%2Dcite][u-report-of]] 等可以用于标记不同的引用目的
- [[https://microformats.org/wiki/h-entry#:~:text=dt%2Dpublished%20%2D%20when%20the%20entry%20was%20published][dt-published]] 标记文章的发布日期
- [[https://microformats.org/wiki/h-entry#:~:text=dt%2Dupdated%20%2D%20when%20the%20entry%20was%20updated][dt-updated]] 标记文章的更新日期

*关于 h-card*

h-card 是用来标记用户信息的，介绍一些我觉得比较有用的：
- [[https://microformats.org/wiki/h-card#:~:text=p%2Dname%20%2D%20The%20full/formatted%20name%20of%20the%20person%20or%20organization][p-name]] 标记个人或组织的全称
- [[https://microformats.org/wiki/h-card#:~:text=u%2Demail%20%2D%20email%20address][u-email]] 标记邮箱，一般标记在 mailto 链接上
- [[https://microformats.org/wiki/h-card#:~:text=u%2Dlogo%20%2D%20a%20logo%20representing%20the%20person%20or%20organization%20(e.g.%20a%20face%20icon)][u-logo]] 标记你的 logo，一般标记在 =<img>= 标签上
- [[https://microformats.org/wiki/h-card#:~:text=u%2Dphoto%20%2D%20a%20photo%20of%20the%20person%20or%20organization][u-photo]] 标记你的头像，一般标记在 =<img>= 标签上
- [[https://microformats.org/wiki/h-card#:~:text=u%2Durl%20%2D%20home%20page%20or%20other%20URL%20representing%20the%20person%20or%20organization][u-url]] 标记你的主页，一般标记在一个链接上
- [[https://microformats.org/wiki/h-card#:~:text=p%2Dnote%20%2D%20additional%20notes][p-note]] 标记额外信息，有人会用来写自我介绍

除了这些，还有标记地址、性别、国籍、出生日期、工作等，感兴趣可以自行探索。

h-card 可以结合 h-entry 的 p-author 用于标记文章的作者信息，
*在这种场景下，h-entry 需要是 h-card 的父元素。*

综上，一个相对完整的 microformats 标记是这样的：

#+begin_src html
  <!doctype html>
  <meta charset="utf-8">
  <title>Hello World</title>
  <body>
    <div class="h-entry"> <!-- 注意 h-entry 是其他属性的父元素，包含了 h-card -->
      <div class="p-author h-card"> <!-- 使用 h-card 结合 p-author 标记作者信息 -->
        <img src="https://aaronpk.com/images/aaronpk.jpg" class="u-photo" width="40">
        <a href="https://aaronpk.com/" class="u-url p-name">Aaron Parecki</a>
      </div>
      <!-- 标记引用的链接，表示回复 -->
      <p>in reply to: <a class="u-in-reply-to" href="https://aaronparecki.com/2018/06/30/11/your-first-webmention">@aaronpk</a></p>
      <!-- 标记回复的内容 -->
      <p class="e-content">Trying out this guide to sending webmentions</p>
      <p>
        <!-- 标记当前文章的 URL -->
        <a href="https://aaronpk.com/reply.html" class="u-url">
          <!-- 标记当前文章的发布日期 -->
          <time class="dt-published" datetime="2018-06-30T17:15:00-0700">July 30, 2018</time>
        </a>
      </p>
    </div>
  </body>
#+end_src

具体如何标记，要看你博客中的 HTML 标记是如何排布的，在标记时注意层级关系就好。
测试阶段可以多利用 [[https://microformats.org/wiki/parsers][Microformats Parsers]] 解析你的文章，检查解析出来的内容是否符合需要。

但 org-mode 会给 =<p>= 和 =<a>= 都加上 =e-content= 和 =u-in-reply-to= ，目前还不知道如何解决。

所幸，不太影响 Webmention 的解析。

都设置好之后就可以向集成了 Webmention 的网站发送通知了，你可以：
- 找到引用文章的 Webmention 入口，填写你的文章 URL 并提交
- 自己构建 POST 请求，或用第三方服务，如 [[https://telegraph.p3k.io/][Telegraph]] 手动发送
- 考虑集成 [[https://webmention.app/][webmention.app]] 等实现自动发送

一般发送之后都会有响应，如果你的 Webmention 没有展示出来，可以基于返回信息进行问题排查。

  =u-in-reply-to= 标记的链接，应该是包含上下分的，一般会作为评论出现。
  如果不包含上下文是没有意义的。
  如果只是引用了一些链接，并没有对于这些链接的回应，
  不需要用 =u-in-reply-to= 标记，直接发送 Webmention 就好了。
